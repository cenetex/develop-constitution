# Develop engineering policy

Use simple English.

1. A user request authorizes the requested engineering work.
2. Use a branch and pull request for normal code changes.
3. Use separate worktrees when developers work in parallel.
4. Developers may push, open or update pull requests, review, merge, deploy,
   verify, and roll back their work.
5. Merge when the relevant checks pass. Do not require an issue, approval,
   label, hold period, evidence record, attestation, or special merger.
6. GitHub commits, pull requests, checks, and deployments are the audit trail.
7. Ask the human once, immediately before an irreversible or materially
   consequential external action.
8. Never commit secrets or overwrite another task's active work.
9. Prefer automatic deployment, health checks, and rollback for reversible
   services.
10. The human may pause, close, revert, or override any task.
